# Maintaining the docs site

This website lives in **`website/`** and is built with
[Docusaurus 3](https://docusaurus.io/). The docs source is plain Markdown under
`website/docs/` — no generated content, so it's easy to keep in sync with the code.

## Running locally

```bash
cd website
npm install     # first time only
npm start       # dev server on http://localhost:3000 with hot reload
```

`npm start` binds `0.0.0.0:3000` (already configured in `package.json`).

## Production build & preview

```bash
npm run build   # static site into website/build/
npm run serve   # serves the production build
```

### The base-URL gotcha

The site defaults to `baseUrl: '/R2K16/'` because **GitHub Pages project sites are served
under the repository name**. When hosting the build at the root of a host (or in a sandbox
preview), override it:

```bash
DOCUSAURUS_BASE_URL=/ npm run build && DOCUSAURUS_BASE_URL=/ npm run serve
```

The dev server (`npm start`) does not care about the base URL.

## Site layout

```
website/
├── docusaurus.config.js    # Site metadata, navbar, footer, theming, mermaid
├── sidebars.js             # Autogenerated sidebars from docs/ structure
├── docs/                   # ← the documentation (Markdown + front matter)
│   ├── intro.md
│   ├── getting-started/    # _category_.json sets label/order
│   ├── architecture/       # engine internals (+ mermaid diagrams)
│   ├── modules/            # per-project reference
│   ├── development/        # CI, security, conventions, this page
│   └── reference/          # repo map, glossary, roadmap, troubleshooting, FAQ
├── src/
│   ├── pages/index.js      # Landing page
│   ├── components/         # Homepage features grid
│   └── css/custom.css      # R2K16 accent colors
└── static/img/             # Logo & favicon
```

### Writing docs

- Create `docs/<category>/<slug>.md` with front matter:

  ```md
  ---
  sidebar_position: 3
  ---
  # Title
  ```

- The sidebar picks it up automatically; `_category_.json` in each folder controls the
  category's label and position.
- Relative links between docs (`. /other-page.md`) get validated at build time —
  `onBrokenLinks: 'throw'` means **broken links fail the build**.
- Code blocks get syntax highlighting for C++, Lua, CMake, bash and more via Prism
  (configured in `docusaurus.config.js`).
- Mermaid diagrams are enabled — fence a block with `mermaid` (see
  `architecture/overview.md` for examples).
- Front matter `title`, `description`, `sidebar_label`, and `sidebar_position` are the ones
  in use.

### What to keep in sync

| When you change… | Update… |
| --- | --- |
| A project's build status | `getting-started/project-status.md` (+ README) |
| A new top-level folder | `reference/repo-map.md` + a module page |
| Roadmap/feature checklist | `reference/roadmap.md` (+ README) |
| CI workflows | `development/ci.md` |
| Library versions | `modules/libraries.md` (+ README) |

## Deployment (GitHub Pages)

The workflow `.github/workflows/docs-deploy.yml` (in the repository root) builds this site
and publishes it to the `gh-pages` branch on every push to `main` that touches
`website/**` or the workflow itself.

To enable it:

1. **Repository Settings → Pages → Source: *Deploy from a branch***, and select `gh-pages`
   (created automatically by the first successful run) — or leave it on *GitHub Actions*.
2. Push to `main` (or adjust the workflow's `on:` triggers).

The published URL is `https://<user>.github.io/R2K16/`.

For other hosts (Netlify, Vercel, plain nginx), build with the right base URL:

```bash
DOCUSAURUS_BASE_URL=/ npm run build
```

and upload `website/build/`.

## Upgrading Docusaurus

```bash
cd website
npm outdated @docusaurus/core @docusaurus/preset-classic @docusaurus/theme-mermaid
npm install @docusaurus/core@latest @docusaurus/preset-classic@latest @docusaurus/theme-mermaid@latest
npm run build   # verify
```

Node ≥ 18 is required (`package.json` engines field).
