# R2K16 Documentation Site

Full codebase documentation for the R2K16 repository, built with
[Docusaurus 3](https://docusaurus.io/) and published at
<https://havaianasdestruido.github.io/R2K16/docs/>.

> The **primary webpage** at <https://havaianasdestruido.github.io/R2K16/> is a
> separate Jekyll site living in [`site/`](../site/) at the repository root.

## Quick start

```bash
cd website
npm install
npm start          # dev server with hot reload (http://localhost:3000)
```

Production build & preview:

```bash
DOCUSAURUS_BASE_URL=/docs/ npm run build   # build with root-based /docs/ paths
DOCUSAURUS_BASE_URL=/docs/ npm run serve   # serve that build
```

`npm run build` defaults to `baseUrl: '/R2K16/docs/'` because on GitHub Pages
the docs are served under `/R2K16/docs/`; override with the
`DOCUSAURUS_BASE_URL` environment variable when hosting elsewhere. The dev
server (`npm start`) ignores this.

## Content

All documentation lives in `docs/` as plain Markdown:

| Folder | Content |
| --- | --- |
| `docs/intro.md` | Introduction |
| `docs/getting-started/` | Prerequisites, build guides, project status |
| `docs/architecture/` | Engine internals (Instance tree, DataModel, jobs, scripting, physics, rendering, networking, serialization, terrain/CSG) |
| `docs/modules/` | Per-project reference for every top-level directory |
| `docs/development/` | CI, FastFlags, security, conventions, docs maintenance |
| `docs/reference/` | Repository map, glossary, roadmap, troubleshooting, FAQ |

Sidebars are autogenerated from the folder structure; ordering comes from
`sidebar_position` front matter and `_category_.json` files. Mermaid diagrams are
enabled. Broken links fail the build.

## Deployment

`.github/workflows/docs-deploy.yml` (repo root) builds this site **and** the
Jekyll primary webpage ([`site/`](../site/)), merges the Docusaurus build under
`/docs/` of the Jekyll build, and publishes the combined artifact to GitHub
Pages on every push to `main` touching `site/**` or `website/**`. Published
URLs: `https://<user>.github.io/R2K16/` (Jekyll) and
`https://<user>.github.io/R2K16/docs/` (these docs).

See `docs/development/docs-site.md` in the built site for the full maintenance
guide.

## Dependency security overrides

Docusaurus 3.10.2 pins several transitive dependencies to versions with known
advisories (including RCE issues in `tinypool`, `serialize-javascript` and
`dompurify`). Upgrading Docusaurus itself is not possible yet — no stable
release contains the fixes — so `package.json` pins the affected transitive
packages to their patched releases with npm `overrides`. `package-lock.json` is
generated from those overrides; keep both files in sync and re-run `npm ci`
plus `npm run build` after changing them. Avoid `npm audit fix --force` here: it
downgrades Docusaurus rather than fixing the nested packages.

With these overrides `npm audit` reports no critical, high or moderate findings.
The five remaining low findings all stem from `deepmerge` (prototype poisoning
in `@svgr/plugin-svgo` → `@svgr/webpack` → `@docusaurus/plugin-svgr`); no
patched `deepmerge` release exists. That code only processes the site's own SVG
assets during the build and never receives untrusted input, so the residual
risk is limited to build time.

One compatibility note: `minimatch` 11 exposes named CommonJS exports instead
of a callable default. `serve-handler` still calls `require('minimatch')` as a
function, but only in its optional `rewrites` / `redirects` / `headers` paths,
which this site does not configure. `npm run build`, `npm start` and
`npm run serve` were smoke-tested with the override in place. If custom
`serve-handler` rules are ever added, either drop that override (accepting the
two moderate `minimatch` / `serve-handler` advisories) or replace
`docusaurus serve` with a maintained static server.
